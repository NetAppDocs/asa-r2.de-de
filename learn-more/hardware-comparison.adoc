= Unterschiede zwischen ASA r2 und anderen ONTAP Systemen
:allow-uri-read: 
:icons: font
:imagesdir: ../media/


[role="lead"]
ASA r2-Systeme sind Hardware- und Softwarelösungen für reine SAN-Umgebungen, die auf All-Flash-Systemen basieren. Sie unterscheiden sich von anderen ONTAP Systemen (ASA, AFF und FAS) in ONTAP-Persönlichkeit, Speicherschicht und unterstützten Protokollen.

Folgende Systeme werden als ASA r2-Systeme klassifiziert:

* ASA A1K
* ASA A90
* ASA A70
* ASA A50
* ASA A30
* ASA A20
* ASA C30




[[personality-differences]]
== Persönlichkeitsunterschiede

Auf einem ASA r2 System ist die ONTAP Software optimiert, um die wesentlichen SAN-Funktionen zu unterstützen und gleichzeitig die Transparenz und Verfügbarkeit von Funktionen und Merkmalen ohne SAN-Bezug einzuschränken. Beispielsweise zeigt der System Manager auf einem ASA r2 System keine Optionen zum Erstellen von Home-Verzeichnissen für NAS-Clients an. Diese optimierte Version von ONTAP wird als _ASA r2 personality_ bezeichnet. ONTAP auf ASA Systemen wird als _ASA ONTAP personality_ bezeichnet. ONTAP auf AFF und FAS Systemen wird als _unified ONTAP personality_ bezeichnet. Die Unterschiede zwischen den ONTAP Personalities werden gegebenenfalls in der ONTAP Befehlsreferenz (man pages), der REST API-Spezifikation und in EMS-Meldungen beschrieben.

Sie können die Persönlichkeit Ihres ONTAP-Speichers vom System Manager oder von der ONTAP-CLI überprüfen.

* Wählen Sie im Menü System Manager *Cluster > Übersicht*.
* Geben Sie in der CLI Folgendes ein: `system node show -personality -is-disaggregated`


Bei ASA r2-Systemen ist die _Persönlichkeit_ _ASA r2_ und der Status von _is-disaggregated_ ist _true_.

Die Persönlichkeit Ihres ONTAP Storage-Systems kann nicht geändert werden.



[[storage-layer-differences]]
== Unterschiede der Speicherebenen

ASA r2-Systeme verwenden eine vereinfachte Speicherschicht, die sich von der Speicherschicht unterscheidet, die von FAS, AFF und ASA Systemen verwendet wird.

.FAS, AFF und ASA -Systeme
Die Speicherschicht von FAS, AFF und ASA Systemen verwendet Aggregate als Basiseinheit der Speicherung. Ein Aggregat besitzt einen bestimmten Satz der im Speichersystem verfügbaren Festplatten. Das Aggregat weist Volumes für LUNs und Namensräume Speicherplatz auf den von ihm besessenen Festplatten zu. Mit diesen Systemen können ONTAP Benutzer Aggregate, Volumes, LUNs und Namensräume erstellen und ändern.

.ASA r2-Systeme
Anstelle von Aggregaten verwendet die Storage Schicht in ASA r2 Systemen Storage Verfügbarkeitszonen. Eine Storage Verfügbarkeitszone ist ein gemeinsamer Storage Pool, der beiden Nodes eines einzelnen HA Paars zur Verfügung steht. Beide Nodes im HA Paar haben Zugriff auf alle verfügbaren Festplatten in ihrer gemeinsamen Storage Verfügbarkeitszone. Ein ASA r2 Cluster mit zwei Nodes verfügt beispielsweise über eine Storage Verfügbarkeitszone, auf die beide Nodes zugreifen können. Ein ASA r2 Cluster mit vier Nodes verfügt über zwei Storage Verfügbarkeitszonen. Jedes HA Paar im Cluster hat Zugriff auf eine der Storage Verfügbarkeitszonen.

Wenn eine Speichereinheit (basierend auf entweder einer LUN oder einem NVMe-Namensraum) erstellt wird, erstellt ONTAP automatisch ein Volume in der entsprechenden Speicherverfügbarkeitszone, um die Speichereinheit aufzunehmen. Das neu erstellte Volume wird automatisch innerhalb der Speicherverfügbarkeitszone platziert, um optimale Leistung und eine ausgewogene Kapazitätsauslastung zu gewährleisten. Die Kapazitätsauslastung wird innerhalb der Speicherverfügbarkeitszone basierend auf Ihrer Version von ONTAP ausgeglichen. link:../administer/space-balancing.html["Erfahren Sie mehr über Kapazitätsausgleich in einem ASA r2-Cluster"^].



[[summary-of-asa-r2-system-differences]]
== Zusammenfassung der Unterschiede im ASA r2-System

ASA r2-Systeme unterscheiden sich von FAS, AFF und ASA -Systemen in folgenden Punkten:

[cols="1h,2,2,2,2"]
|===
|  | ASA r2 | ASA | AFF | FAS 


 a| 
*ONTAP-Persönlichkeit*
| ASA r2 | ASA | Virtualisierung | Virtualisierung 


 a| 
*Unterstützung für SAN-Protokolle*
| Ja. | Ja. | Ja. | Ja. 


 a| 
*Unterstützung des NAS-Protokolls*
| Nein | Nein | Ja. | Ja. 


 a| 
*Unterstützung der Speicherschicht*
| Zone der Storage-Verfügbarkeit | Aggregate | Aggregate | Aggregate 
|===
Aufgrund dieses automatisierten und vereinfachten Ansatzes zur Speicherverwaltung sind bestimmte System Manager-Optionen, ONTAP -Befehle und REST-API-Endpunkte auf einem ASA r2-System nicht verfügbar oder nur eingeschränkt nutzbar. Da beispielsweise die Volume-Erstellung und -Verwaltung für ASA r2-Systeme automatisiert ist, wird das Menü *Volumes* im System Manager nicht angezeigt und die  `volume create` Befehl wird nicht unterstützt. link:cli-support.html["Erfahren Sie mehr über nicht unterstützte ASA R2-Befehle"] .

Die Hauptunterschiede zwischen ASA r2 Systemen und FAS, AFF und ASA Systemen, die für die ONTAP Befehlszeilenschnittstelle (CLI) und REST API relevant sind, werden im Folgenden beschrieben.

.Standardmäßige Erstellung von Speicher-VMs mit Protokolldiensten
Neue Cluster enthalten automatisch eine Standard-Datenspeicher-VM mit aktivierten SAN-Protokollen. IP-Daten-LIFs unterstützen iSCSI- und NVMe/TCP-Protokolle und verwenden standardmäßig die  `default-data-blocks` Dienstrichtlinie.

.Automatische Volume-Erstellung
Durch Erstellen einer Storage-Einheit (LUN oder Namespace) wird automatisch ein Volume aus der Storage-Verfügbarkeitszone erstellt. Dies führt zu einem vereinfachten und gemeinsamen Namespace. Durch Löschen einer Speichereinheit wird das zugeordnete Volume automatisch gelöscht.

.Änderungen an Thin Provisioning und Thick Provisioning
Storage-Einheiten werden auf ASA r2-Storage-Systemen immer über Thin Provisioning bereitgestellt. Thick Provisioning wird nicht unterstützt.

.Änderungen an der Datenkomprimierung
Temperaturempfindliche Storage-Effizienz wird auf ASA r2-Systemen nicht angewendet. Auf ASA r2-Systemen basiert die Komprimierung nicht auf _Hot_-Daten (auf die häufig zugegriffen wird) oder _Cold_-Daten (auf die selten zugegriffen wird). Die Komprimierung beginnt, ohne auf Daten zu warten, die kalt werden.
